# Projekty dokumentów sprzedażowych — MVP-51

**projekt do przeglądu prawnego — nie do podpisu ani wysyłki klientowi.**

Pakiet dotyczy usług rekrutacji IT świadczonych przez właściciela. HireOS pozostaje jego narzędziem single tenant; klient nie otrzymuje konta w panelu. Dokumenty nie ustalają cen ani nie zatwierdzają zgodności prawnej.

## Dokumenty i kolejność użycia

1. [Oferta dla firmy](oferta.md) — zakres i warunki do uzgodnienia.
2. [Umowa o usługi rekrutacyjne](umowa-rekrutacyjna.md) — projekt zobowiązań stron.
3. [Role RODO i warianty umowy dotyczącej danych](role-rodo.md) — karta kwalifikacji roli oraz projekty udostępnienia i powierzenia.
4. [Checklista onboardingu](onboarding.md) — przygotowanie zlecenia, shortlisty i rozliczeń.

Każde pole wymagające wyboru lub uzupełnienia zawiera znacznik **[DECYZJA WŁAŚCICIELA]**. Właściciel uzupełnia kopię poza repozytorium, uzgadnia warunki z klientem i zleca przegląd prawny. Znacznik nie oznacza, że można samodzielnie wybrać kwalifikację prawną sprzeczną z rzeczywistym procesem. Proponowane klauzule również wymagają akceptacji całego dokumentu.

- [DECYZJA WŁAŚCICIELA] Zatwierdzić z prawnikiem ostateczne wersje, formę działalności, dane stron, zasady wynagrodzenia i dokumenty dotyczące danych w ramach MVP-52.
- [DECYZJA WŁAŚCICIELA] Wyznaczyć miejsce przechowywania podpisanych dokumentów, wersję, datę zatwierdzenia i osoby upoważnione do ich akceptacji.

Nie wpisywać do repo danych stron, kontaktów, podpisów, CV, danych kandydatów, rzeczywistych warunków finansowych ani aktywnych linków do shortlist. Szablony zawierają wyłącznie opisy pól. Zatwierdzone kopie przechowuje się poza repo w miejscu z ograniczonym dostępem.

Zakres produktu i zadania: [SPEC](../../SPEC.md), [MVP-46/47/48/51/52 w planie](../../planning/tasks.json). Checklista opisuje funkcje planowane; ich obecność w planie nie jest dowodem wdrożenia. Brak wymaganej funkcji wstrzymuje odpowiedni etap onboardingu.
